# Roadmap

## v0 — Specification (current)

- [x] `SPEC.md`: folder format, node modes, gates, working-dir contract,
      fan-out, runs/versions/cache, scheduling, engines, traces, layout,
      compilation, CLI, viewer.
- [x] `DECISIONS.md` with reasons and sources.
- [x] `AGENTS.md` so any agent can author a workflow from the format alone.
- [x] Two example workflows converted from real processes:
      `video-to-blog` and `shorts-pipeline`.
- [ ] Dry-read both examples against the spec and list every construct the
      spec needed to add. (Done during writing; re-check before v1.)

## v1 — Runner + read-mostly viewer

Target: run `examples/video-to-blog` end to end on a real recording with the
Claude engine.

Runner:
- `flowy compile` with the validations in SPEC §11.
- `flowy run` with `agent` and `script` modes, gates (`approve`), `foreach`,
  versions, recursive signatures with verify-on-resume, global concurrency,
  stagger.
- Claude adapter (SPEC §8.1) with `trace.jsonl` / `result.json`.
- `flowy status`, `approve`, `rerun --feedback`, `use`, `skip`, `trace`,
  `stop`.

Viewer:
- `flowy serve`: graph from manifest + `layout.canvas`, live reload on file
  change, node cards (status, version, cost, edge sizes, stale/gate), item
  checklist, node panel (outputs, versions side by side, trace, approval
  form). Buttons call the same code paths as the CLI.
- `flowy layout` auto-layout when the canvas file is missing; drag writes
  positions back.

Out of scope for v1: `chat`, `wait`, locks, `before:`, other engines.

## v2 — The interactive parts

Target: run `examples/shorts-pipeline` end to end.

- `wait` mode with filesystem events.
- `chat` mode: open the engine interactively in the version dir; resume the
  session of a gated agent node.
- Locks and `before:` pre-checks.
- Large-file references (`_refs.json`, `--add-dir`).
- Codex adapter; capability flags exercised for real.
- OpenTimelineIO as the cut-list artifact in the example, with the editor
  draft generated by the last node.

## v3 — Editing on the canvas

- Add/remove edges and nodes from the viewer, written back to
  `workflow.yaml` and `nodes/*.md`; the manifest is regenerated.
- Workflow-level versioning helpers (snapshot / diff two workflow folders).
- Node library: reuse a node file across workflows by reference.

## Not planned

Hosted service, embedded chat, auto-generated context, Electron, editor
round-trips. See `DECISIONS.md` D10.
